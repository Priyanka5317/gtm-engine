The qualification gate

Every GTM pipeline needs a stage that removes opportunities before anyone spends effort on them. Here it is work authorisation. Two rules carry the whole thing: only a stated requirement is a wall, because silence is not a rejection; and a wall and a downgrade are different outcomes, because a citizenship requirement cannot be negotiated while a missing sponsorship policy can be priced. Paste a sentence from a real posting and every verdict cites the phrase that produced it.

Adapter coverage

13 implemented, 12 verified against live vendors. Those are two different claims, so the suite prints both and names every gap. No mocks anywhere: the thing most likely to break is not the parsing, it is a vendor quietly renaming a field, and a mock hides exactly that.

    Python 3.11, no dependencies, no API keys, no accounts. Runs entirely in your browser; nothing is sent anywhere. The sample pipeline in the repo is synthetic. The real table is not published, because it carries company names, recruiter identities and private notes: the engine ships, the data does not.
